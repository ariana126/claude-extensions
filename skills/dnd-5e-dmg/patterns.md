# Patterns

## Encounter Difficulty Calculation
**When to use**: designing or evaluating any combat encounter.
**How**: sum party XP thresholds (Easy/Medium/Hard/Deadly) by level → sum monster XP → apply Encounter Multiplier by monster count → compare adjusted XP to party thresholds.
**Trade-offs**: precise and consistent, but doesn't account for monster ability synergies, terrain, or party tactics — sanity-check against Ch 3's "Challenge Rating" caution (a low-level party can still be one-shot by a single high-CR monster with an outsized single attack).

## Core Assumptions Inversion
**When to use**: starting a new campaign world.
**How**: take one of the 5 default assumptions (gods oversee the world / world is untamed / world is ancient / conflict shapes history / world is magical) and invert it, then trace the downstream implications.
**Trade-offs**: produces a distinctive setting fast, but inverting too many assumptions at once can make the world incoherent — the book implicitly suggests inverting 1-2, not all 5.

## Ten Sentences NPC Build
**When to use**: any NPC who will recur or matter beyond a single scene.
**How**: one sentence each for Occupation/History, Appearance, Abilities, Talent, Mannerism, Interactions, Useful Knowledge, Ideal, Bond, Flaw/Secret.
**Trade-offs**: fast and reliably produces a usable character, but is overkill for background extras — reserve for NPCs with narrative weight.

## Villain Objective × Method Factoring
**When to use**: designing any villain, to avoid cookie-cutter motivations.
**How**: roll/pick an Objective (Immortality/Influence/Magic/Mayhem/Passion/Power/Revenge/Wealth) independently from a Method (the large d20 category table of tactics).
**Trade-offs**: guarantees variety across multiple villains in a campaign; requires the DM to still weave objective and method into a coherent backstory rather than leaving them as disconnected rolls.

## Dungeon Build Stack (Creator → Purpose → History → Factions)
**When to use**: designing any dungeon, random or bespoke.
**How**: layer Creator (who built it) → Purpose (why it exists) → History (what happened to the creators) → current Inhabitants/Factions (who lives there now).
**Trade-offs**: produces coherent, motivated dungeons fast; multi-faction results add design overhead but pay off with non-combat player options.

## Location-Based / Event-Based Adventure Build Order
**When to use**: starting any new adventure.
**How**: Location-based — goals → NPCs → location detail → introduction → climax → encounters. Event-based — villain → villain's actions → party goals → NPCs → villain reactions → key locations → intro/climax → encounters.
**Trade-offs**: location-based is faster to build and easier to run reactively; event-based better supports intrigue/mystery adventures but requires more upfront NPC/motivation work.

## Mystery/Intrigue Modules on the Event-Based Skeleton
**When to use**: layering a whodunit or political-power-struggle adventure onto the standard event-based build.
**How**: Mystery adds Victim/Suspects/Clues (over-provision clues); Intrigue adds Villains (0/1/many) + an Influence resource (spent like Inspiration or tracked like Renown).
**Trade-offs**: mysteries risk being unsolvable if clues are too sparse — the book explicitly recommends erring toward too many clues rather than too few.

## Downtime Activity Chassis (Days → Check → d100 Table)
**When to use**: designing any new downtime activity not covered by existing rules.
**How**: set a days-spent cost scaled to scope (settlement size, item rarity, renown level) → require a relevant ability check → resolve outcome via a d100(+modifier) table.
**Trade-offs**: consistent and easy for players to learn once they've seen one downtime activity; low-stakes downtime activities don't need this much structure — reserve for activities with real risk/reward.

## Quick Monster Stats (CR-table lookup + adjust + recompute)
**When to use**: needing a fast, usable monster without full stat-block design.
**How**: pick expected CR → pull AC/HP/attack/damage/save DC off the Monster Statistics by CR table → adjust to concept → recompute final CR as the average of independently-derived defensive (HP/AC) and offensive (damage/attack or save DC) ratings.
**Trade-offs**: much faster than full stat-block creation; loses the flavor of unique special abilities unless you separately bolt on 1-2 special traits.

## Social Interaction 4-Step Resolution
**When to use**: any NPC negotiation/persuasion scene.
**How**: set Starting Attitude → play Conversation (attitude shifts at most 1 step via ideal/bond/flaw) → Charisma check vs. a DC keyed to attitude+ask-size → decide if repeating is fruitful.
**Trade-offs**: keeps social scenes consistent and fair across different NPCs; must stay invisible to players or it feels mechanical rather than roleplayed.

## Artifact Property Budgeting
**When to use**: creating or reskinning a campaign-defining artifact.
**How**: assign up to 4 minor + 2 major beneficial properties and 4 minor + 2 major detrimental properties from the d100 tables (or invent equivalents); always pair power with cost.
**Trade-offs**: guarantees artifacts feel simultaneously desirable and dangerous; re-rolling properties each time an artifact resurfaces keeps repeat use fresh across campaigns.

## Random Dungeon Two-Pass Generation
**When to use**: needing a dungeon fast, or wanting inspiration to riff on.
**How**: Pass 1 — layout (Starting Area → Passages → Doors → Chambers → Stairs, iterated to a size limit). Pass 2 — stocking (Purpose → Contents → Motivation/Hazard/Trap/Trick as indicated).
**Trade-offs**: fast and endlessly varied; produces occasional incongruous results the DM should feel free to override rather than forcing sense onto them.
